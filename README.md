# 世界书自动开关管理器

SillyTavern 独立前端扩展，根据用户提供的《产品需求说明书 v2.0》开发。

条目成功进入请求、AI 完整回复后，按照统一的「延迟 → 冷却 → 恢复激活资格」循环管理。默认延迟 0、冷却 1：第 1 回合成功注入，第 2 回合关闭，第 3 回合恢复原有激活资格。

**当前版本 1.3.1，以 SillyTavern 1.19.x 为准。** 1.3.0 已在隔离的官方 1.19.0（`06bde93`）实例上用真实前端跑通备选、分支、回退、刷新、工具调用、群聊等端到端检查（模型由本地模拟）；1.3.1 在此时间线底座上新增可设置的「单回合绿灯触发上限（用户提及优先）」（目前完成本地自动测试与压力验证，真实酒馆 1.19 实例尚未对 1.3.1 重跑）。1.18.x 仍可加载运行，但 1.3.x 没有在 1.18 上完整重测；面板底部会显示当前酒馆版本。不依赖酒馆助手、Extras、服务器插件、远程脚本或额外模型服务。

## 安装

推荐在酒馆「扩展 → 安装扩展」中填入仓库地址：

```text
https://github.com/cjhkcjgk3-sys/worldbook-switch-manager
```

也可以手动安装：

1. 解压安装包，得到 `worldbook-switch-manager` 文件夹。
2. 将整个文件夹放入酒馆的 `data/<你的用户目录>/extensions/`。默认用户通常是 `data/default-user/extensions/`。也可使用全局扩展目录 `public/scripts/extensions/third-party/`。
3. 确认文件层级为 `extensions/worldbook-switch-manager/manifest.json`，避免多套一层目录。
4. 刷新酒馆，点击主页面左下角的魔术棒（扩展）按钮，在菜单中点击「世界书自动开关管理器」。如果宿主没有魔术棒菜单，扩展会自动退回扩展设置面板。如扩展管理页面中处于停用状态，启用它。

从 GitHub 下载源码 ZIP 时，解压文件夹可能名为 `worldbook-switch-manager-main`，请重命名为 `worldbook-switch-manager` 后再放入扩展目录。

Android 使用相同的酒馆服务端扩展目录；手机浏览器里打开酒馆后，点击魔术棒菜单里的「世界书自动开关管理器」即可完成全部核心操作。

## 使用

- **入口在主页面左下角的魔术棒（扩展）菜单。** 点击菜单里的「世界书自动开关管理器」打开管理器面板；关闭弹窗后再次打开，会保留搜索词、展开的世界书和临时勾选。
- 开启「启用管理器」及「成功注入后自动冷却」，设置延迟和冷却回合。
- 如需防止单回合同时触发过多绿灯设定条目，可勾选「启用单回合绿灯触发上限（用户提及优先）」（默认关闭），并在旁边的「单回合绿灯上限（条）」输入框随时设置上限数量（默认 5 条）。
- 不选任何精细范围时，默认管理当前聊天使用的所有世界书条目。
- 在「设置自动管理范围」中展开世界书，勾选需要管理的条目，或选择「整本管理」。整本管理持续包含以后新增的条目。
- **清空全部精细选择会恢复全部管理。** 真正停止冻结应关闭总开关。
- 临时操作时，把「选择用途」切换到「选择临时冻结条目」，勾选条目，输入回合数后点击「冻结所选」。这套勾选不会改变自动管理范围。
- 「解除所选手动冻结」只撤销手动条件。自动冷却仍有效时，条目继续冻结。
- 「常驻（蓝灯）条目也参与自动冷却」默认关闭：蓝灯条目每回合都会注入，默认不让它们自动冷却；手动冻结对蓝灯照常有效。
- 「AI 连续回复也算一回合」默认关闭：不输入内容直接让 AI 再说一段时，仍算同一回合；打开后每段连续的 AI 回复各算一回合（群聊里多个角色依次回复也会各算一回合）。
- 面板底部的「清除本聊天插件数据」会删掉当前聊天所有楼层（含备选回复）里本插件写的记录，不动世界书和聊天正文；清除后会从服务器读回聊天文件确认，保存失败时会提示重试。

每条状态显示下一次**新回合**的延迟、自动冷却和手动冻结剩余回合。正在生成时暂停临时操作，避免修改本次请求的冻结条件。

## 规则与保存

- 开启意味着恢复原生激活资格；绿灯仍需关键词等条件满足，蓝灯仍按原生规则处理。
- 启用单回合绿灯触发上限时，仅在扫描副本上按「用户最新消息提及 > 较早用户消息提及 > 仅模型回复提及」优先级（同级按最近消息与命中位置先后）保留前 N 条（可在「单回合绿灯上限（条）」自定义），超出条目本轮临时禁用、不写入楼层注入记录、不进冷却，后续回合可顺位触发；同一 `(world, uid)` 多处挂载只占 1 个名额；蓝灯、向量与未管理条目不占绿灯名额。重摇（`swipe`／`regenerate`）时排除待替换的旧 AI 回复，避免旧回复关键词占名额。
- 只在本次世界书扫描的副本上临时关闭，不保存世界书，也不改正文、关键词、概率、深度或原本禁用状态。
- 全局参数、开关与精细范围保存在酒馆扩展设置。**从 1.3.0 起，冷却和手动冻结记录保存在聊天楼层里**（消息的 `extra.wsm`，备选回复各自一份），因此：
  - **切换备选回复**：每个备选记着它自己那次请求注入了什么，切到哪个备选就按哪个算；新的备选按本回合开始时的状态过滤。
  - **重新生成 / 继续**：沿用同一用户消息的回合；继续时与原回复的记录合并。
  - **删楼回退**（例如聊到 20 楼，回到 16 楼删掉后面）：状态就是 16 楼当时的状态，不用重置；删除中间某一楼不会改写现在的状态。
  - **开分支 / 检查点**：分支复制了楼层，也就带着当时的状态；两条线之后各走各的。
  - **刷新页面、切换聊天再回来**：从楼层里恢复，不再清零。
  - 编辑消息、隐藏消息不会清掉记录；隐藏的用户消息仍算一回合。
- 连续发出的多条用户消息（中间没有 AI 回复，例如请求失败后直接发新消息）只算一回合。工具调用消息不影响回合计数。
- 一次生成多个备选（`n>1`）时，每个备选都有自己的记录。
- 手动冻结先作为“草稿”存在聊天元数据里，从下一回合开始生效；下一次回复完成时写进该回合的记录，之后同样跟着楼层走（回退到那之前，冻结就不存在）。草稿只在它创建时的那个位置有效（含在哪条回复之后创建），被复制到别的分支、或从更早的楼层开分支时不会误生效。
- 只有实际请求包含该条目，且收到对应完整 AI 回复，才确立自动周期。预览、静默请求、代写用户、失败、停止都不写记录。工具调用的后续请求与首个请求算同一次回复；工具调用后的后续请求失败时，整次回复都不算成功（工具前输出的那段文字也不写记录）。
- Text Completion 下，如果生成过程中有其他插件并行发了后台请求（无法区分是哪次请求注入的），本回合不启动自动冷却，并在面板提示。
- 相同回合只计一次；延迟中再次注入不重置周期。已开始的周期保留开始时的时长，新参数适用于后续周期。生成过程中修改延迟/冷却回合数，本回合按回复完成那一刻的设置记录。
- 手动停止生成：半截回复不写记录。之后点重新生成、右滑新备选或「继续」把半截续完，都算同一回合，只按最终完成的那条回复记注入；左滑回到半截的那个备选时视为本回合未注入。停止后不重新生成、直接发新消息，半截回复留在历史里算一回合（回合数照常推进），但不记注入，所以条目在下一回合仍可注入。
- 手动冻结会保存在每个回合的快照里。正常冻结几条到几十条时体积很小；一次冻结上万条并聊很多回合，聊天文件会明显变大（实测 1 万条、30 回合约 13.7MB）。
- 总开关关闭时不过滤、不写记录。自动冷却开关关闭时只停用自动条件；手动冻结继续生效。
- 1.2.x 及更早版本的聊天没有记录，从现有回合数接着计数，不会恢复旧进度。
- 导出或分享聊天文件时会带上这些记录（只有世界书名、条目编号和回合数）。
- 当前群聊列表合并启用成员的世界书；一个用户消息后的多名角色回复共享同一回合。
- 自动管理范围里如果有已经删除或改名的世界书，面板会列出来并提供「清理失效选择」。

## 验证状态与边界

已通过规则/场景自动测试（`npm test` 85/85）、扩展检查（`npm run check`）、长聊天与 1 万条目压力测试（含开启绿灯上限的 4 万楼层扫描基准），以及模拟页 Chromium 4 视口（1280×1000、390×844、320×568、740×360）与 1 万条目界面压力检查；1.3.0 时间线基线另曾在官方 1.19.0 隔离实例完成 52 项端到端、21 项复核与 24 项停止组合检查（同时装着酒馆助手 JS-Slash-Runner 4.12.2，模型回复由本地模拟服务生成）。

**1.3.1 合并后的绿灯上限及界面改动尚未在官方 1.19.0 隔离实例重跑 e2e，也尚未在用户正在使用的酒馆、真实模型服务、Text Completion 后端与 Android（SillyDroid）实机完成验收；MVU、记忆类插件共存未测。** 可按 [验收步骤](docs/ACCEPTANCE.md) 复现。

成功注入的核实采用「原生预算通过的激活条目 + 最终请求文本 + 完整回复」联合证据。Chat Completion 的世界书前/后位置还核对原生提示词槽位，避免把聊天记录里的同文误认为注入。其他插入位置或 Text Completion 中，如果同文已存在于聊天或角色字段，采用保守策略，暂不启动该条目的自动周期。含动态宏的世界书正则也暂不重复执行来推断结果，避免产生额外变量写入。这些场景需要目标宿主进一步验证和完善；详见 [验证记录](docs/VALIDATION.md)。

如果其他扩展在本扩展最后观察之后继续改写请求，或服务端再次裁剪/改写上下文，浏览器侧无法直接证明模型最终收到的全文。首次验收应使用实际发送请求核对。

## 卸载

在扩展管理器中停用或删除扩展，刷新页面，必要时删除安装目录。没有需要恢复的世界书修改。聊天楼层里的记录不影响酒馆和其他插件，可在卸载前用「清除本聊天插件数据」逐个聊天清掉。全局扩展设置保留，便于重新安装后继续使用。

## 开发

运行环境零构建、零第三方依赖。开发检查需要 Node.js 20.11+；打包需要 Python 3。

```sh
npm test
npm run check
npm run test:stress
npm run package
# 真实酒馆端到端（需单独的 1.19 实例，见 tests/e2e/README.md）
node tests/e2e/e2e.mjs
```

可选浏览器测试：

```sh
npm install --no-save playwright
npm run test:browser
```

大书列表按需展开，每本先显示 100 条，点击「显示更多」继续；全选与冻结仍作用于全部匹配条目。

默认使用 `/usr/bin/chromium`，也可设置 `WSM_CHROMIUM` 指向本机 Chromium。测试只启动独立模拟页面，不安装到现有酒馆。

API 依据见 [API-SOURCES.md](docs/API-SOURCES.md)，验证范围见 [VALIDATION.md](docs/VALIDATION.md)。
