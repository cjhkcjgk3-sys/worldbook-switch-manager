# 世界书自动开关管理器

SillyTavern 独立前端扩展，根据用户提供的《产品需求说明书 v2.0》开发。

条目成功进入请求、AI 完整回复后，按照统一的「延迟 → 冷却 → 恢复激活资格」循环管理。默认延迟 0、冷却 1：第 1 回合成功注入，第 2 回合关闭，第 3 回合恢复原有激活资格。

**当前支持 SillyTavern 1.19.x 正式版。** 开发时核对的官方源码为 1.19.0、提交 `06bde939fb1e9c4c8d8641d810f0a916b5bce127`。其他版本会显示版本提示并停止管理。不依赖酒馆助手、Extras、服务器插件、远程脚本或额外模型服务。

## 安装

推荐在酒馆「扩展 → 安装扩展」中填入仓库地址：

```text
https://github.com/cjhkcjgk3-sys/worldbook-switch-manager
```

也可以手动安装：

1. 解压安装包，得到 `worldbook-switch-manager` 文件夹。
2. 将整个文件夹放入酒馆的 `data/<你的用户目录>/extensions/`。默认用户通常是 `data/default-user/extensions/`。也可使用全局扩展目录 `public/scripts/extensions/third-party/`。
3. 确认文件层级为 `extensions/worldbook-switch-manager/manifest.json`，避免多套一层目录。
4. 刷新酒馆，在扩展设置中展开「世界书自动开关管理器」。如扩展管理页面中处于停用状态，启用它。

从 GitHub 下载源码 ZIP 时，解压文件夹可能名为 `worldbook-switch-manager-main`，请重命名为 `worldbook-switch-manager` 后再放入扩展目录。

Android 使用相同的酒馆服务端扩展目录；手机浏览器里打开酒馆后，核心操作全部在扩展设置页完成。

## 使用

- 开启「启用管理器」及「成功注入后自动冷却」，设置延迟和冷却回合。
- 不选任何精细范围时，默认管理当前聊天使用的所有世界书条目。
- 在「设置自动管理范围」中展开世界书，勾选需要管理的条目，或选择「整本管理」。整本管理持续包含以后新增的条目。
- **清空全部精细选择会恢复全部管理。** 真正停止冻结应关闭总开关。
- 临时操作时，把「选择用途」切换到「选择临时冻结条目」，勾选条目，输入回合数后点击「冻结所选」。这套勾选不会改变自动管理范围。
- 「解除所选手动冻结」只撤销手动条件。自动冷却仍有效时，条目继续冻结。

每条状态显示下一次**新回合**的延迟、自动冷却和手动冻结剩余回合。重新生成、切换候选和续写继续使用该用户消息对应的原回合。正在生成时暂停临时操作，避免修改本次请求的冻结条件。

## 规则与保存

- 开启意味着恢复原生激活资格；绿灯仍需关键词等条件满足，蓝灯仍按原生规则处理。
- 只在本次世界书扫描的副本上临时关闭，不保存世界书，也不改正文、关键词、概率、深度或原本禁用状态。
- 全局参数与精细范围保存在酒馆扩展设置；进度保存在各聊天元数据。聊天导出/复制的元数据也可能携带进度。
- 只有实际请求包含该条目，且收到对应完整 AI 回复，才确立自动周期和推进新回合。预览、静默请求、代写用户、失败、取消不计数。
- 相同逻辑回合只计一次；延迟中再次注入不重置周期。已开始的周期保留开始时的时长，新参数适用于后续周期。
- 总开关关闭后立即停止对后续扫描施加冻结。暂停期间正常完成的对话仍推进聊天时间，但不新建自动周期；重新启用时已到期的周期自然失效。
- 自动冷却开关关闭时只停用自动条件；手动冻结继续按总开关控制。自动管理范围不约束用户明确指定的临时手动冻结。
- 历史编辑、删除或检测到失效分支时，清除该聊天旧进度并在界面说明。其他聊天不受影响。普通追加消息、刷新、切换聊天会保留有效进度。
- 当前群聊列表合并启用成员的世界书；每次实际扫描只控制宿主提供的条目，一个用户消息后的群聊回复共享同一回合。

## 验证状态与边界

已通过规则/事件自动测试、扩展文件与语法检查，以及独立 Chromium 界面的桌面、390px 和 320px 布局及操作测试。浏览器测试使用模拟宿主。

**尚未在用户的真实 SillyTavern 与 Android 设备完成验收，也未录制 PRD 9.1 要求的真实生成演示。** 可按 [验收步骤](docs/ACCEPTANCE.md) 复现。

成功注入的核实采用「原生预算通过的激活条目 + 最终请求文本 + 完整回复」联合证据。Chat Completion 的世界书前/后位置还核对原生提示词槽位，避免把聊天记录里的同文误认为注入。其他插入位置或 Text Completion 中，如果同文已存在于聊天或角色字段，采用保守策略，暂不启动该条目的自动周期。含动态宏的世界书正则也暂不重复执行来推断结果，避免产生额外变量写入。这些场景需要目标宿主进一步验证和完善；详见 [验证记录](docs/VALIDATION.md)。

如果其他扩展在本扩展最后观察之后继续改写请求，或服务端再次裁剪/改写上下文，浏览器侧无法直接证明模型最终收到的全文。首次验收应使用实际发送请求核对。

## 卸载

在扩展管理器中停用或删除扩展，刷新页面，必要时删除安装目录。没有需要恢复的世界书修改。已有聊天进度与扩展设置仅作为命名空间数据保留，便于重新安装后续用。

## 开发

运行环境零构建、零第三方依赖。开发检查需要 Node.js 20+；打包需要 Python 3。

```sh
npm test
npm run check
npm run package
```

可选浏览器测试：

```sh
npm install --no-save playwright
npm run test:browser
```

默认使用 `/usr/bin/chromium`，也可设置 `WSM_CHROMIUM` 指向本机 Chromium。测试只启动独立模拟页面，不安装到现有酒馆。

API 依据见 [API-SOURCES.md](docs/API-SOURCES.md)，验证范围见 [VALIDATION.md](docs/VALIDATION.md)。
