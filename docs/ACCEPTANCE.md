# 真实酒馆验收步骤

本文件是可复现步骤，尚不是实测通过记录。请在测试聊天中进行，记录实际 SillyTavern 版本和后端；不要将包含凭证的请求头放入截图。

## PRD 9.1 三回合演示

1. 新建测试角色和聊天。挂载一本混合世界书，放入：
   - 绿灯条目「雷电将军」：关键词「雷电将军」，正文是较长人物资料，另加入唯一标记 `WSM_ACCEPT_RAIDEN_2026`。
   - 蓝灯条目「世界规则」：加入唯一标记 `WSM_ACCEPT_RULES_2026`。
   - 原本禁用条目：加入唯一标记 `WSM_ACCEPT_DISABLED_2026`。
2. 导出该世界书作为验收前基线。使用 Chat Completion，在提示词管理器中开启世界书前/后槽位，并给够世界书预算。
3. 打开本扩展，延迟 0、冷却 1，仅精细选择「雷电将军」。
4. 第 1 次发送「雷电将军在做什么？」。在开发者工具 Network 中核对实际生成请求的 messages：人物唯一标记和规则唯一标记存在；禁用标记不存在。等待完整回复。
5. 第 2 次仍发送含「雷电将军」的用户消息。请求中人物标记缺席，规则标记继续存在。等待完整回复。
6. 对第 2 个 AI 回复重新生成，核对人物标记仍缺席，完成回合数仍为 2。切换候选也不扣回合。
7. 第 3 次发送含关键词的用户消息。人物标记恢复存在；如不含关键词则应继续缺席。开启资格不强制注入。
8. 再次导出世界书，与基线进行 JSON 内容比较，确认正文、关键词、启用、概率、位置和深度完全相同。
9. 录制上述操作与请求证据。不要只用聊天回复提到人物作为注入证明。
