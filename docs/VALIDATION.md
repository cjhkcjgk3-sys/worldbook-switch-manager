日期：2026-11-23。环境：官方 SillyTavern 1.19.0（`06bde93`）独立克隆、独立数据目录与端口；本地模拟 OpenAI 兼容服务（流式/非流式/工具调用/失败/慢速）；无头 Chrome 驱动真实前端；酒馆助手（JS-Slash-Runner 4.12.2）同时加载。没有接触用户自己的酒馆，没有调用付费模型。

| 前提 | 结果 |
| --- | --- |
| MESSAGE_RECEIVED 时写入 `mes.extra`、`swipe_info[i].extra`、用户消息 extra，随后自动落盘（流式、非流式、工具调用、群聊） | 通过 |
| 新备选在 GENERATION_STARTED 前已复制 extra，可清除继承；左右切换、`/delswipe` 后 extra 与显示的备选一致 | 通过 |
| 重新生成：STARTED 后才删除旧回复；继续：type 为 `continue`，`send_date` 会变（不能用作身份） | 通过 |
| 工具调用：后续请求以 STARTED('normal') 开始，激活条目可能变少 | 通过（据此沿用首个请求证据） |
| quiet 请求：CCSR 的 type 为 `quiet`；在其他插件的 MESSAGE_RECEIVED 中发起时，它的 ENDED 先于本插件的 RECEIVED | 通过（据此改为计数嵌套） |

## 第四步：手动停止后的组合操作（2026-11-23）

`tests/e2e/stop.mjs` 在真实 1.19.0 上实测 8 个场景 24 项，全部通过（`stop-1.19-results.json`），未发现 bug。判断依据是模拟服务实际收到的请求里有没有条目，以及消息 `extra`。模拟服务新增 `/mock/control`，让接下来的 N 个请求（或工具后续请求）变慢，方便中途停止。

| 场景 | 结果 |
| --- | --- |
| S1 流式停止 → 重新生成 | 半截无记录；重新生成注入并记录（第 1 回合）；下一回合冷却；聊天文件一致 |
| S2 流式停止 → 右滑新备选 → 左滑回半截 | 只有新备选有记录；回到半截时本回合视为未注入，下一回合条目可注入 |
| S3 流式停止 → 继续 | 续完后按续写请求记录（第 1 回合），下一回合冷却 |
| S4 停止 → 重新生成再停止 → 重新生成 | 两次停止均无记录，最终回复记录，下一回合冷却 |
| S5 停止 → 直接发新消息 | 半截留在历史、无记录；新消息为第 2 回合且条目可注入；第 3 回合冷却 |
| S6 已有完整回复的楼层上新备选中途停止 → 切回旧备选 | 半截备选无记录；旧备选记录恢复；下一回合冷却 |
| S7 非流式等待中停止 → 重新生成 | 无消息无记录；重新生成记录；下一回合冷却 |
| S8 工具调用后续请求中途停止 → 重新生成 | 无记录；重新生成后的最终回复记录（第 1 回合）；下一回合冷却 |

同时复跑：`npm test` 76/76、`npm run check`、`e2e.mjs` 52/52、`review.mjs` 21/21。

## 剩余边界

- 用户正在使用的酒馆、真实模型服务、Android 实机与其他扩展组合尚未实测。本轮已在全新数据目录的官方 1.18.0 隔离实例验证 1.2.0 魔术棒入口与原生生成回归。
- 1.19 保留源码与能力合同支持，本轮原生实例主验收是 1.18.0；不将它扩展为全部补丁版本或预发布版的实测结论。
- 含动态宏的世界书正则不会为取证被重复执行；部分特殊插入位置/Text Completion 与历史或角色字段同文时，仍保守等待可确认的注入，并提示原因。
- 后续扩展监听器或服务端再改写请求时，仍需核对最终链路。
- 群聊、工具调用递归、自动续写，以及与其他自动生成扩展并发的组合未完成完整矩阵；本次不新增这些承诺。
