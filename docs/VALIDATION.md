## 注入证据的边界

1. 原生世界书预算通过的 `WORLD_INFO_ACTIVATED` 仍不是发送成功的证明，因此必须再检查最终请求和完整回复。
2. Chat Completion 的世界书前/后槽位还验证原生 `promptManager` 的来源集合。提示词管理器关闭该槽位时，即使聊天历史包含相同正文，也不建立冷却。
3. 其他位置与 Text Completion 缺少同等细粒度的原生来源标识。如果同文出现在历史/角色字段，插件保守地等待后续可确认的注入，并在页面提示。这一小类情况下，自动冷却不能保证对每次实际注入都启动。
4. 为保护原有变量，检测到世界书正则需要再次运行动态宏时，不会重复执行这些宏来取证；对应条目等待可确认的注入。这类配置不在当前已验证的自动触发路径内。
5. 监听器顺序通过 `makeLast` 排在注册时已存在的监听器之后。若其他扩展之后又改写最终请求，或服务端另行转换内容，仍需与实际请求/服务端行为对照。

以上是当前实现的剩余边界，不将它们算作 PRD 的全量真实验收通过。下一步按 `ACCEPTANCE.md` 在目标酒馆运行，针对发现的版本/后端差异完善适配。没有修改 PRD 的产品目标。
